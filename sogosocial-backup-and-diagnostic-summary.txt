7. Origin of "Account reauth failed" and Exception Conversion:
   - The string "Account reauth failed" originates in the device's Google Play
     Services (com.google.android.gms / GmsCore) process as the statusMessage of
     a com.google.android.gms.common.api.Status with statusCode = 16
     (CommonStatusCodes.CANCELED = 16).
   - On Android 14+ (API 34+), CredentialProviderFactory.kt (lines 92-104)
     routes requests through CredentialProviderFrameworkImpl.kt (lines 131-173),
     which receives android.credentials.GetCredentialException from GmsCore and
     converts it via ConversionUtils.kt (lines 78-106) into a Jetpack
     GetCredentialException preserving error.message ("[16] Account reauth failed.").
   - On Pre-Android 14 (CredentialProviderPlayServicesImpl.kt lines 125-127 ->
     CredentialProviderGetSignInIntentController.kt lines 224-236),
     Identity.getSignInClient(context).getSignInCredentialFromIntent(data)
     (zbat.class in play-services-auth:21.4.0) throws ApiException(status) with
     statusCode == CommonStatusCodes.CANCELED (16), which is converted into
     GetCredentialCancellationException("16: Account reauth failed.").
   - GoogleProvider.java (line 931) checks isAccountReauthFailed(errorMessage)
     (message.contains("Account reauth failed")) before checking
     e instanceof GetCredentialCancellationException (line 935), retries once via
     handleAccountReauthFailed() (lines 853-887), and rejects on the second
     failure.

8. Is [16] an Actual Google Status Code 16 or Plugin-Generated?
   - BOTH:
     1) 16 is the real Google Play Services status code
        CommonStatusCodes.CANCELED = 16 returned by GmsCore with statusMessage
        "Account reauth failed.".
     2) In GoogleProvider.java (lines 858-863), handleAccountReauthFailed() also
        hardcoded the literal string:
        "Google Sign-In failed: [16] Account reauth failed. The plugin cleared
         Credential Manager credential-selection state and retried once..."
        without interpolating e.getMessage(), e.getType(), or runtime
        signingSha1 into call.reject(...).

9. Compatibility Issues in @capgo/capacitor-social-login 8.5.7:
   - Issue 1: GoogleProvider.java line 542 passed `context` instead of `activity`
     to `credentialManager.getCredentialAsync(context, ...)` (fixed in our
     updated patch).
   - Issue 2: GoogleProvider.java lines 858-863 omitted runtime `signingSha1`,
     `clientId`, `e.getClass()`, `e.getType()`, and `e.getMessage()` from the
     rejected error string (fixed in our updated patch).
   - Issue 3: In `GetGoogleIdOption.Builder` (`googleid:1.1.1`),
     `filterByAuthorizedAccounts` defaults to `true` (`iconst_1` in bytecode),
     and `GoogleProvider.java` lines 514-516 only call
     `setFilterByAuthorizedAccounts(true)` when true, never calling `false`.
   - Issue 4: Unconditional `getAuthorizationResult()` call after ID token
     extraction (fixed by our early-return patch in `handleSignInResult`).

function countOccurrences(haystack, needle) {
  let count = 0;
  let pos = 0;
  while ((pos = haystack.indexOf(needle, pos)) !== -1) {
    count++;
    pos += needle.length;
  }
  return count;
}

let updatedContent = content;
let appliedAny = false;

for (const patch of patches) {
  const patchedCount = countOccurrences(updatedContent, patch.patched);
  if (patchedCount === 1) {
    continue;
  }
  if (patchedCount > 1) {
    console.error(`[patch-social-login] ERROR: Patch "${patch.name}" appears multiple times in GoogleProvider.java.`);
    process.exit(1);

  const unpatchedCount = countOccurrences(updatedContent, patch.unpatched);

    );
    process.exit(1);
  }

  updatedContent = updatedContent.replace(patch.unpatched, patch.patched);
  appliedAny = true;
}

for (const patch of patches) {
